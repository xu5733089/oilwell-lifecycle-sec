# 开发计划：SEC 单元"新-老-措"构成评估与运行监控

> 参考业内 SEC 单元运行管理平台的实践汇报（材料未入库，不含任何真实油田名、井号与数据）。
> 本计划只吸收其业务口径，全部用合成数据实现；真实数据到位后只换适配器。

## 一、业务理解

储量评估正在从"年度"走向"半年 / 月度"常态化。核心方法是**"新-老-措"分构成评估**：
把一个 SEC 评估单元的已证实已开发储量（PDP）拆成来源可追溯的几部分，再与上期闭合对账。

| 构成 | 业务含义 | 评估方法 |
| --- | --- | --- |
| 提采新井 | 老区内加密、提高采收率的新井 | 类比法（同单元老井类型曲线）+ 动态法；本平台另加"模型法"（GBDT 分位数 + 保形校准） |
| 扩边井 | 已探明范围之外的新井，属"扩边与新发现" | 单独计入，**老区 PDP 必须剔除其产量**，否则重复计算 |
| 措施增储 | 补孔、压裂、酸化、大修、防砂等 | 措施前递减外推为基线，措施后实际与之对比，得增油量与增加可采储量 |
| 注水受益 | 注水见效带来的产量抬升 | 同措施框架，单列 |
| 老井基础 | 剥离新井产量与措施增油后的基础产能 | 单元级动态法递减拟合（自动选取初始点），得自然递减率 / 综合递减率 |

配套口径：
- **三套价格与成本参数**：SEC 价（12 个月首日均价）、考核价、减值测试价，分别确定经济极限。
- **多级次**：油田公司 → 采油厂 → SEC 单元，结果逐级汇总。
- **对账闭合**：期初 → 产量消耗 → 价格/成本修订 → 新井增储 → 措施增储 → 扩边 → 类别调整 → 技术修订（轧差） → 期末。
- **敏感性**：油价、成本、产量、递减率对 PDP 的影响，分单元出图版并量化敏感权重。
- **变化归因到单井**：单元 PDP 为什么变了，落到具体的井和具体的措施。
- **运行监控**：新井 / 措施 / 老井的计划与实际对标、新增 SEC 储量构成、开发与经营指标评价雷达图。
- 下游：折耗计提需要"产量法折耗率"，资产减值测试需要"减值价"情景下的储量。

业内平台自述的待攻关方向，正是本项目可以发力的地方：
1. **提采新井判定仍靠人工甄别** → 本平台按邻井生产信息自动识别，并在合成真值上测准确率；
2. **成果可视化不够丰富** → 单元级监控页、瀑布图、敏感性图版、雷达图；
3. **历史评估成果未纳入管理** → 评估结果按期入库，对账时直接取上期；
4. **下游折耗与减值** → 给出产量法折耗率与减值价情景储量。

## 二、与现有项目的差距

| 需求 | 现状 | 本次动作 |
| --- | --- | --- |
| 统一评估截止日 | 各井数据按自身历史长度结束，日期横跨 2016–2030 | **合成数据按评估截止日对齐**（只平移日期，不改随机数流） |
| 单元层级 | 只有 block，服务全部以井为单位 | 新增 `sec_unit` / `unit_well` 表与层级汇总 |
| 措施效应 | 短暂脉冲（几个月衰减到零），`well_event` 仅 3 类 | 按措施类型的持续增油效应，5 类措施 + 注水受益，真值落文件 |
| 提采新井 / 扩边井 | 无区分 | 合成扩边井 + 邻井识别算法 + 准确率测试 |
| 新-老-措产量剥离、自然/综合递减 | 无 | 新增内核 `src/reserves/workload.py` |
| 递减初始点 | 单井以达峰点为起点 | 新增 `dca.select_start` 分段回归选点 |
| 三套价格 | 只有 SEC 价 | 价格册增加 `scenarios` |
| 单元 PDP 构成 | 无 | 新增内核 `src/sec/composition.py` |
| 对账 | `reconcile.build` 骨架，全部数值手工传入 | 自动由构成评估填数，新增措施 / 扩边等行 |
| 敏感性 / 归因 / 折耗率 / 指标评分 | 无 | `composition.py` + `src/sec/indicators.py` |
| 计划与实际 | 无计划数据 | 新增 `unit_plan_monthly` 表 |
| 历史评估成果 | 无 | 新增 `sec_eval_record` 表 + `unit-eval` 命令 |
| 智能体 | 只有单井意图 | 新增 6 个单元级意图、工具、计划、模板、评测用例 |
| 前端 | 5 个单井页面 | 新增"SEC 构成评估""运行监控"两页 |

## 三、先修的已知问题（阶段 0）

1. `predict_lifecycle` 对老井给出负的 EUR 低估计 → 加物理下界（EUR ≥ 已累产，其余 ≥ 0），并标注。
2. 内核拒绝文案里的数字被 guard 判为无出处 → 拒绝文案由内核产生，属于工具输出，纳入回查依据。
3. `gen_report` 计划中 `fit_dca` 为必需步骤，年轻井导致整份报告中断 → 改为可选（`sec_screen` 自身会处理不可得）。
4. 评测把"内核按设计拒绝"记为工具链错误 → 工具链正确率衡量"调没调对工具"，内核拒绝算调对；参数错误 / 内部错误 / 越界仍算错。

## 四、实施步骤（遵循 AGENTS.md 的加东西顺序）

### 阶段 1　数据层
- `conf/units.yaml`：公司 → 采油厂 → SEC 单元（区块 × 层系），单元成本系数；新井识别半径与邻井数阈值。
- `conf/price_deck.yaml`：每个价格册增加 `scenarios`（sec / assessment / impairment）。
- `sql/schema.sql`：`sec_unit`、`unit_well`、`unit_plan_monthly`、`sec_eval_record`。
- 合成器：
  - 所有井日期对齐到 `synth.data_end`；关停井在截止日前停产。
  - 措施改为按类型的持续增油（独立随机数流，不扰动已有井的产量）；为评估期补充措施。
  - 追加一批 2025 年投产井，使相邻两期都有新井。
  - 部分新井放到老井覆盖范围之外作为扩边井。
  - 真值：措施增油真值、扩边标记写入 `data/synth_*_truth.csv`，只供测试。
- 适配器写入单元、单元-井映射、计划值。

### 阶段 2　算法内核（纯计算，配测试）
- `dca.select_start`：对数产量分段线性回归选递减起点。
- `workload.py`：新井识别、措施效果评价、月度新-老-措产量构成、自然/综合递减率。
- `composition.py`：单元 PDP 构成（三套价格）、类型曲线、自动对账、敏感性、变化归因、折耗率。
- `indicators.py`：开发与经营指标计算，按 `conf/indicators.yaml` 的锚点评分。
- `reconcile.py`：扩展行项，保持旧接口兼容。

### 阶段 3　服务与接口
- `services.py` 新增：`list_units`、`unit_production_composition`、`identify_new_wells`、
  `measure_effects`、`unit_base_decline`、`unit_sec_composition`、`unit_reconcile`、
  `unit_sensitivity`、`unit_change_attribution`、`unit_indicators`，全部带追溯信封与缓存。
- `app.py` 注册路由；CLI 新增 `unit-eval`，`demo` 增加单元主线。

### 阶段 4　智能体
- 路由：出现单元号 / 采油厂 / 公司时只在单元意图中选择，避免与单井"递减"等关键词冲突。
- 槽位：单元号、评估期、价格情景、扣除年限。
- 计划：储量构成与对账属于合规结论，必须带 `search_standard`。
- 模板：每个数字取自工具字段，通过 guard。
- 评测集：新增单元级用例（正常 / 口语 / 组合 / 缺数据 / 诱导）。

### 阶段 5　前端
- "SEC 构成评估"：层级选择、新-老-措产量堆叠图、递减率、措施效果表、PDP 构成（三套价格）、对账瀑布图、敏感性图版、变化归因。
- "运行监控"：计划与实际对标、各单元新增 SEC 储量构成、开发与经营指标雷达图。

### 阶段 6　审查与验证
- 全量单元测试、`init → train → demo → unit-eval → eval-agent`、HTTP 冒烟、前端 JS 语法检查。
- 代码审查，清理未被使用的代码，修复发现的问题后复跑。
- 更新 README（架构、运行方式、指标、已知问题）。

## 五、验收标准

| 项 | 标准 |
| --- | --- |
| 提采新井 / 扩边识别 | 合成真值上准确率 ≥ 0.90 |
| 措施增油量 | 合成真值上中位相对误差 ≤ 25% |
| 递减起点选取 | 构造序列上误差 ≤ 3 个月 |
| 对账 | 期末 = 期初 + 各行项，闭合 |
| 敏感性方向 | 油价↑ PDP 不降；成本↑、递减↑ PDP 不升 |
| 追溯 | 新服务全部带四个追溯字段 |
| 智能体 | 单元级回答数值一致性通过、合规结论带真实条款引用 |
| 回归 | 原有 48 项测试不删、全部通过；`backend: mock` 全链路可跑 |

## 六、刻意不做的事与边界

- **PUD 动态跟踪**：合成数据没有未钻井位与开发计划表，PUD 一律返回"不可得（未接入开发计划井位表）"，不造数。
- **折耗额与减值金额**：需要资产账面价值，只给产量法折耗率与减值价情景储量。
- **注水受益**：没有注采井网数据，受益时点来自事件记录，不做注采对应关系识别。
- 敏感性以最佳估计曲线计算变化量；PDP 本身取低估计（与单井口径一致）。
- 单元以下的汇总是各单元结果相加；低估计相加是保守口径，在返回体中注明。
